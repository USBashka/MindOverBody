# Rusterize в MOB

Карта сновидений — приложение на Rust с реализацией `rusterize::Application`,
скомпилированное в WebAssembly. Это не JavaScript-перерисовка похожего интерфейса:
геометрия, Canvas-команды, расположение локаций, связи, огоньки ОС, изображения,
движение персонажей, выбор, перенос и масштабирование выполняются кодом Rust.
Браузерный адаптер Rusterize исполняет его проверенный display list RZ02.

Исходный фреймворк: [USBashka/Rusterize](https://github.com/USBashka/Rusterize),
commit `92db95ba70e27e3426247397b3698805024fdacf`. Необходимые исходники ядра и
браузерного адаптера находятся в `vendor/rusterize`; лицензии MIT и Apache-2.0
сохранены. Изменения адаптера перечислены в `vendor/rusterize/UPSTREAM.md`.

## Разделение ответственности

| Компонент | Ответственность |
| --- | --- |
| `native/src/lib.rs` | Настоящее Rusterize-приложение, сцена, камера, pointer/key события, персонажи |
| `src/rusterize.js` | Передача локальных данных и RGBA-иллюстраций, вызовы и события моста |
| `vendor/rusterize/hosts/web` | Официальный Canvas 2D адаптер Rusterize с двумя дополнительными методами |
| `public/rusterize/app.wasm` | Собранное ядро карты, включённое в offline-кэш PWA и Android assets |
| HTML-интерфейс MOB | Дневник, Markdown, экранная клавиатура, камеры, Google OAuth и доступные списки |

HTML-редактор обеспечивает IME, системную экранную клавиатуру, выделение текста и
доступность. Эти функции не реализованы в общем Canvas API Rusterize 0.1.
В карте Tab свободно переводит фокус к HTML-элементам; список локаций позволяет
открывать записи без работы с графическим Canvas. Стрелки перемещают камеру,
Home показывает все места, `+`/`−` меняют масштаб, Enter открывает выбранное место.

Android-приложение упаковывает полный локальный интерфейс в системный WebView;
карта использует тот же Rusterize/WASM-код. Это WebView + Canvas 2D, а не прямой
JNI-вызов Android Canvas. Rust-ядро не зависит от DOM и может использовать нативный
адаптер Rusterize отдельно, но такой адаптер не является текущей оболочкой MOB.

## Сборка и проверки

Требуются Rust 1.85+ и цель `wasm32-unknown-unknown`:

```sh
rustup target add wasm32-unknown-unknown
npm run build:rust
npm run build
```

Сборка использует локальную path-зависимость и `native/Cargo.lock`. Готовый
`app.wasm` также хранится в репозитории: обычная сборка сайта доступна без Rust.
После изменения Rust-кода нужно пересобрать WASM перед сборкой сайта/APK.

```sh
cargo fmt --manifest-path native/Cargo.toml --check
cargo test --manifest-path native/Cargo.toml --locked
cargo clippy --manifest-path native/Cargo.toml --all-targets -- -D warnings
node native/check-web.mjs
```

Последняя команда использует установленный Playwright и Chromium
(`CHROMIUM_PATH=/path/to/chromium`, по умолчанию `/usr/bin/chromium`) и запускает
временный HTTP-сервер только на localhost. Проверяет настоящий WASM на desktop
и mobile: пиксели RGBA-изображения, открытие и перенос локации, клавиатуру и выход
по Tab, масштабирование, движение, reduced motion, отсутствие постоянных кадров
в простое, resize/DPI и идемпотентное уничтожение. Скриншоты — `/tmp/mob-map-check`.
Rust-тесты проверяют преобразование координат, сохранение якоря масштабирования,
отмену переноса, маршруты персонажей и валидность нативной сцены Rusterize.

## Контракт моста

`await createDreamMap(canvas, {nodes, edges, characters, onOpen, onMove})` возвращает
контроллер с `update(graph)`, `zoom(factor)`, `reset()`, `focus(id)`, `position(id)`
и `destroy()`. При смене раздела вызов `destroy()` обязателен: он снимает события,
наблюдатели размера, анимацию и освобождает WASM-экземпляр. Асинхронная загрузка
изображения от предыдущего обновления не может изменить новую сцену.

Локация: `{id, name, x?, y?, count, lucidCount, image?}`. Связь:
`{source, target, count}`. Персонаж: `{id, name, locations: [id, ...], image?}`.
Изображение — локальный Blob, data URL либо объект с `src`/`dataUrl`. Сторонние
URL не загружаются: иллюстрации дневника не создают запросов на чужие серверы.
Изображения декодируются и уменьшаются один раз до 128×128, затем Rust хранит
обычные `rusterize::Image` и рисует их через общий Canvas API.

Начальная сцена — 1000×700 условных единиц; координаты не зависят от CSS-размера
и плотности пикселей. При отсутствии координат применяется детерминированная
раскладка. `onMove(id, {x,y})` вызывается после завершённого переноса; приложение
сохраняет координаты в локальной базе. Отменённый указатель возвращает локацию
на прежнее место. Клик и перенос различаются порогом в 5 CSS-пикселей.

Передача ограничена 500 локациями, 2500 связями, 200 персонажами и буфером
256 КиБ. После загрузки не происходит сетевых запросов или постоянного опроса
моста. Персонажи используют Rusterize Frame events; reduced motion и отсутствие
персонажей выключают анимацию. Скрытая вкладка приостанавливается адаптером.
