# Google Диск: синхронизация без сервера

MOB хранит дневник, иллюстрации, теги и прогресс в IndexedDB на устройстве. Google Диск подключается только по желанию пользователя. Обычная работа приложения, импорт Somnio и JSON-экспорт не требуют аккаунта, интернета или Google.

## Как подключить веб-версию

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включите **Google Drive API** в API Library.
3. В **Google Auth Platform → Branding / Audience** настройте экран согласия. В режиме Testing добавьте свой Google-аккаунт в список тестировщиков.
4. В разделе **Data Access** добавьте scope `https://www.googleapis.com/auth/drive.appdata`.
5. Создайте OAuth Client ID типа **Web application**. Добавьте точный origin сайта в **Authorized JavaScript origins**, например `https://usbashka.github.io`. Путь `/MindOverBody/` в origin не входит. Для разработки отдельно добавьте `http://localhost:5173` или фактический порт.
6. Скопируйте **Client ID** вида `123456789-….apps.googleusercontent.com` в настройки MOB и нажмите «Подключить Google Диск».
7. Выберите аккаунт и разрешите доступ. Затем запустите синхронизацию.

Client ID — публичный идентификатор приложения. Client secret не нужен: не вставляйте его в приложение, репозиторий или настройки. На статическом GitHub Pages секреты хранить нельзя. Не требуется настраивать redirect URI: веб-версия использует Google Identity Services Token Model с окном согласия.

Google может применять свои ограничения к проектам в режиме тестирования. Для широкого доступа настройте публикацию OAuth-приложения в Console и выполните требования Google. Без собственного Client ID дневник и локальные резервные копии остаются полностью работоспособными.

## Android APK

В Android-приложении вход выполняется через нативные Google Play services, а не внутри WebView. Для APK нужен OAuth-клиент типа **Android** в том же Cloud-проекте: package name `ru.usbashka.mob` и SHA-1 сертификата, которым подписан устанавливаемый APK. Для debug- и release-сборки могут понадобиться разные клиенты. Фактический сертификат и порядок сборки описаны в Android-документации проекта.

Нативный мост `MOBAndroid.requestDriveToken(webClientId, callbackName)` возвращает краткоживущий токен с разрешением `drive.appdata`. На Android поле Web Client ID для этого запроса не требуется. Устройство должно иметь совместимые Google Play services. JSON-резервные копии доступны и без них.

## Что сохраняется в облаке

Используется скрытая папка **appDataFolder**, доступная только приложению с этим OAuth-проектом. MOB не запрашивает чтение остальных файлов Google Диска. В обычном списке файлов резервные копии не отображаются; управлять данными приложения можно в настройках Google Drive. Это не папка, которую нужно выбирать вручную.

Каждое устройство записывает отдельный JSON-снимок. При синхронизации MOB сначала читает снимки всех устройств, объединяет записи по ID и датам изменения, затем обновляет только свой снимок. Одновременная работа двух устройств не перезаписывает единственную копию другого. Для появления последних изменений с другого устройства запустите синхронизацию и на нём. Это ручная синхронизация, а не постоянное соединение.

В облачный снимок входят записи, встроенные иллюстрации, теги, отметки удаления, прогресс курса и архив альтернативных версий. Настройки устройства не отправляются. При разных версиях одного объекта основная версия выбирается по времени изменения; удаление выигрывает при равном времени. Альтернативная версия сохраняется в `conflicts` резервной копии и может быть восстановлена через приложение. Отметки удаления сохраняются, чтобы старое устройство не возвращало удалённую запись при следующей синхронизации.

## Приватность и ограничения

- Токен доступа находится только в памяти текущего сеанса. Он не сохраняется в IndexedDB, localStorage, JSON-экспорте или репозитории. После перезапуска или истечения токена потребуется повторно подключить Google Диск.
- Сетевые запросы идут напрямую из браузера к Google. У MOB нет сервера и собственной авторизации.
- Дневник и иллюстрации в JSON не зашифрованы дополнительно приложением. Защита облачной копии зависит от вашего Google-аккаунта. Экспортированный JSON содержит личные записи: храните его в подходящем месте.
- При сетевой ошибке или некорректной облачной копии загрузка останавливается, локальная база продолжает работать. Ошибки не считаются успешной синхронизацией.
- Приложение запрашивает постоянное локальное хранилище, когда браузер это поддерживает. Очистка данных сайта или удаление приложения может удалить локальный дневник. Регулярный JSON-экспорт остаётся полезной независимой резервной копией.
- Максимальный JSON-файл — 100 МБ; иллюстрации встроены в него. Для больших дневников уменьшайте размеры изображений перед добавлением.

## Диагностика

**`origin_mismatch`:** сравните адрес сайта с Authorized JavaScript origins; учтите протокол и порт, исключите путь.

**`access_denied` / аккаунт не разрешён:** проверьте тестировщиков OAuth-проекта и настройки аудитории.

**Ошибка 403:** убедитесь, что Drive API включён именно в проекте Client ID и выдан scope `drive.appdata`.

**Окно входа не открывается:** разрешите всплывающие окна и загрузку `accounts.google.com`, повторите подключение. В Android вход должен открываться через системные Google Play services.

**Разрешение истекло:** подключите Google Диск повторно. Дневник остаётся на устройстве.

**Изменения другого устройства не появились:** убедитесь, что на обоих устройствах один Google-аккаунт и OAuth-проекты совпадают; запустите синхронизацию на источнике, затем на принимающем устройстве.
